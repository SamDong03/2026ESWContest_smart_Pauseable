# 치매 관련 반복행동 근거와 가전 이벤트 시뮬레이션

검토일: 2026-10-05. 연구용 기능이며 임상 진단기나 환자 행동을 검증된 정확도로 예측하는 모델이 아니다.

## 결론

실제 치매 환자의 반복행동 정답이 붙은 가전 이벤트가 충분하지 않을 때, **문헌에서 행동 유형을 가져오고, 실제 관찰 데이터는 생활 맥락을 참고하며, 가정은 명시한 합성 시나리오로 시스템을 시험**할 수 있다. 하지만 합성 데이터를 늘리는 것은 실제 환자 수나 임상 검증 표본 수를 늘리는 일이 아니다.

이번 구현은 ‘어떤 조건에서 어떤 가전 이벤트가 나올 수 있는가’를 생성하는 조건부 시뮬레이션이다. ‘이 환자가 다음에 냉장고를 열 확률’ 같은 실제 미래 예측은 구현하거나 검증하지 않았다. 예측 모델을 만들려면 환자별 실제 시간 이력과 미래 구간 평가가 별도로 필요하다.

공개가 어려운 이유를 개인정보 하나로 단정하지 않는다. 동의 범위, 연구 승인, 모집 규모, 설치 비용, 센서와 가전의 차이, 행동 라벨링 비용도 자료 확보의 제약이다. MINDER처럼 공개된 자료도 있지만 그 자료의 진단 정보가 매 이벤트의 반복행동 정답인 것은 아니다.

## 왜 이 방식을 선택했나

GAN이나 LLM으로 환자 로그처럼 보이는 기록을 대량 생성해도, 실측 정답이 없으면 생성기의 가정을 학습하게 된다. 이번에는 검토 가능한 작은 시나리오를 사용한다. 각 문 열기는 닫기와 짝이 있고 전자레인지는 running → done → idle 순서를 지킨다. 일부러 누락시킨 센서 시험은 그 사실을 표시한다.

한 가지 중요한 실험은 **같은 센서 기록에 두 가지 가능한 설명을 붙이는 것**이다.

- 냉장고 6회 열기: 기억이 나지 않아 확인 / 샐러드 재료를 나눠 꺼내기.
- 전자레인지 여러 번 사용: 완료를 잊고 다시 가열 / 여러 사람의 식사를 한 접시씩 가열.

입력이 완전히 같으면 baseline, IF, AE 어느 것이든 이유를 알아낼 수 없다. 따라서 ‘치매 행동 확정’이 아니라 ‘평소와 다른 반복 후보’로 출력하고, 사용자 루틴/재실/보호자 확인 같은 추가 맥락이 필요하다. 이번 기능은 이 한계를 감추지 않고 `observability_pairs.json`에 기록한다.

## 구현 흐름

1. `deploy/research/evidence.json`에 논문 URL, 근거 종류, 한계, 시나리오 연결을 기록한다.
2. 선택적으로 `COVID_kitchen.csv.zip`을 읽어 MINDER 시간대 참고값을 계산한다. 가구별 관찰 날짜 앞 70%만 사용하고, 경계 다음 하루를 제외한 이후 자료는 분포 변화 비교용으로 남긴다. 가구별 정규화 후 평균하므로 기록이 많은 한 가구가 모두 지배하지 않게 한다.
3. 기존 한 달 검증 코드의 정상 가정 합성 이력을 재사용한다. 이 정상 가정 이력은 MINDER로 학습한 환자 행동이 아니다.
4. 이 합성 이력에 기존 특징 생성기와 baseline/IF/AE 코드를 적용한다. 정상 가정 이력을 시간순 학습/보정/검증으로 나누고 사이에 120분을 비운다. baseline도 학습 구간만 사용한다.
5. 그 이력보다 미래 날짜에 출처 연결 시나리오를 별도로 생성한다. 문헌은 유형을 정하고, 횟수/간격은 공학적인 민감도 시험값이다. `low/medium/high`는 이벤트 밀도이며 치매 중증도가 아니다.
6. 기존 54개 수치 특징으로 매분 평가하고, 규칙 결과와 IF/AE 결과를 나란히 저장한다. 센서 누락 시험에는 판단 보류를 표시한다.
7. 시나리오별 결과, 동일 입력 비교, 모델 정상 가정 holdout 경보율, 실행 로그를 저장한다. MQTT/Central/TTS/실제 가전으로 보내지 않는다.

한 달 시험의 정상 이력 특징은 실행 시간을 줄이려고 하루 24개 끝점으로 계산한다. 매일 표본의 분 위치를 `(42 + 17 × 날짜 인덱스) mod 60`으로 돌려 정각만 볼 때 짧은 사용이 누락되는 편향을 줄였다. 시나리오 평가만 1분 간격이며 실서비스 주기를 바꾸지 않는다. 여전히 전체 매분 이력을 학습한 것은 아니므로 이 실험의 모델/기준값을 운영에 복사하면 안 된다. 같은 seed의 가설/정상 쌍은 의도적으로 중복 입력이므로 독립적인 환자 표본 수로 세지 않는다.

## 어떤 시나리오인가

- 반복 가설: 냉장고 재확인, 전자레인지 작업 재시작.
- 정상 비교: 재료 꺼내기, 여러 접시 가열, 단일 사용, 야간 간식, 보호자 방문.
- 별도 문제: 과제 누락 가설, 오래 가열하기. 반복행동 탐지 성공률 계산에 넣지 않는다.
- 센서 문제: 같은 이벤트 중복 수신, 닫힘 이벤트 누락.

공통 기본값은 냉장고 확인 3/6/10회, 간격 45~120초, 열림 지속 2~20초이다. 전자레인지 반복 횟수는 밀도별 2/3/5회, 가열 60~120초, 다음 동작까지 30~120초이다. **모두 소프트웨어 시험값이지 논문에서 추출한 환자 통계나 의료 기준이 아니다.**

MINDER는 시나리오 시작 시간대 추출에만 반영된다. 반복 횟수, 문 열린 시간, 환자 중증도, AE 가중치, 운영 baseline을 그 데이터에서 정하지 않는다. 공개 CSV의 `oven-use`를 전자레인지로 바꾸지 않고, 냉장고 이벤트에 실제로 없던 열림/닫힘 상태를 실측처럼 복원하지 않는다. 원본 복제나 가구 ID의 결과 보고도 하지 않는다. 집계했다고 정식 익명성 보장이 생기는 것은 아니므로 배포 전 데이터 이용 조건을 별도로 확인한다.

## Docker 실행

기존 `Dockerfile.pi`와 Pi 서비스는 그대로 둔다. 아래는 로컬 Linux/WSL에서 `Pauseable.ai/ha` 폴더를 현재 디렉터리로 했을 때의 명령이다.

```sh
docker build -f Dockerfile.research -t pauseable-ha-evidence:20261005 .
mkdir -p outputs/evidence_research
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --pids-limit 128 --memory 2g --cpus 2 \
  --tmpfs /tmp -v "$PWD/outputs/evidence_research:/results" \
  pauseable-ha-evidence:20261005
```

Linux에서 bind mount 디렉터리 쓰기 권한은 컨테이너 UID 10001에 맞춘다. Windows 드라이브를 WSL에 마운트한 이번 검증에서는 쓰기 가능했다. 같은 결과 디렉터리는 덮어쓰지 않는다. 재시험은 명령 끝에 `python src/run_ha_evidence_research.py --output-dir /results/run2`처럼 새 경로를 준다.

Compose가 설치된 환경에서는 `docker compose -f compose.research.yaml --profile research run --build --rm evidence-research`로 동일 연구 서비스를 실행할 수 있다. 실행 컨테이너는 네트워크가 없지만 이미지 최초 빌드에는 다운로드가 필요하다.

MINDER를 쓰려면 허용된 방법으로 확보한 ZIP을 `/reference/COVID_kitchen.csv.zip`에 읽기 전용 마운트하고 `--minder-zip /reference/COVID_kitchen.csv.zip`을 추가한다. 원본은 Docker 이미지나 Git에 포함하지 않는다.

```sh
docker run --rm --network none --read-only --tmpfs /tmp \
  -v "$PWD/outputs/evidence_research:/results" \
  -v "/absolute/path/to/COVID_kitchen.csv.zip:/reference/COVID_kitchen.csv.zip:ro" \
  pauseable-ha-evidence:20261005 python src/run_ha_evidence_research.py \
  --output-dir /results/minder_run --minder-zip /reference/COVID_kitchen.csv.zip
```

## 결과를 읽는 방법

먼저 `simulation_report_ko.md`를 연다. 기준 변경표, 실제 연구 모델의 기준값, 전체 사례 결과표, 사례별 입력/특징/판단 파일 링크가 한글로 정리된다. 이 파일은 시뮬레이션이 끝나면 자동 생성된다.

`report.json`의 `completed`는 프로그램 완료 여부다. 임상 성능이 좋다는 뜻이 아니다. `production_eligible=false`와 `clinical_validation=false`를 유지한다.

`scenario_results.csv`에서 각 가설과 정상 비교 사례의 `rule/if/ae_max_level`을 함께 본다. 가설에서 경보가 많아도 정상 비교에서 같은 경보가 나면 원인 구분에 실패하는 것이다. 생성 비율을 마음대로 정했으므로 전체 정확도 하나를 계산해 발표하지 않는다.

`cases/.../events.csv` → `features.csv` → `scores.csv`를 순서대로 보면 입력이 어떻게 점수가 되는지 공부할 수 있다. `provenance.json`에는 출처 ID와 숫자의 가정이 있다. `training_log.txt`, `synthetic_model/manifest.json`에는 모델 분할 시점, 수렴 여부, 검증값이 있다. `run_log.jsonl`은 단계별 경과 시간 로그다.

### 기준값을 읽는 예

기존 냉장고 단시간 반복 조건은 ‘10분 열기 횟수 ≥ max(4, floor(학습 p95)+1)’와 ‘10분 상태 변화 횟수 ≥ max(6, floor(학습 p95)+1)’가 함께 성립하는지를 본다. 그 외 30분/1시간 지속, IQR/백분위 기반 점수, 야간 보정, 연속 창 승격이 합쳐진다. 따라서 냉장고 4회라는 한 숫자가 최종 판정 전체를 뜻하지 않는다. 이 기존 규칙의 숫자는 이번 논문에서 얻거나 수정한 것이 아니다.

`p95`는 학습 구간 특징값의 95백분위다. ‘치매일 확률 95%’가 아니다. IF는 학습한 행동 특징에서 쉽게 고립되는 정도를 점수로 만들고, AE는 입력을 복원하면서 생기는 오차를 쓴다. 각각의 연구용 attention/risk 경계는 학습과 분리된 정상 가정 보정 구간 점수의 95/99백분위다. `holdout`은 그 경계 설정에도 사용하지 않은 이후의 시험 구간이다.

정상 가정 holdout에서 경보가 8% 나왔다는 결과는 ‘치매 탐지 정확도 92%’가 아니다. 전제상 정상으로 만든 구간에서 경보가 그만큼 나왔다는 뜻이며, 실제 환자 민감도나 실제 가정 오탐률로 일반화할 수 없다.

## 실제로 남은 일

실사용자 동의하에 가전 이벤트와 보호자 확인을 함께 모아 정상 요리, 재확인, 센서 오류의 구분 자료를 만들어야 한다. 환자에게 반복행동을 유도하거나 위험 가전을 켜두는 방식으로 수집하지 않는다.

공통 baseline을 문헌의 증상 설명만으로 다시 수치화하지 않는다. 실제 관찰의 관찰 가능 시간/요일/식사·방문 맥락을 검토하고, 개인별 정상 가정 구간에 이상행동이 섞이지 않았는지 확인한다. IF/AE는 ‘익숙해짐’과 ‘안전함’을 구분하지 못하므로 보호자 검토 없이 모든 데이터를 자동 정상으로 재학습시키지 않는다.

다음 모델 변경 후보는 세션 진행/완료, 장시간 상태 유지, 방문/다인 가구 맥락, 센서 가용성 특징이다. 특징을 늘리면 스키마 버전과 재학습/기존 모델 호환성도 바꿔야 한다. 이번 작업에서는 운영 스키마와 기존 경보 정책을 변경하지 않았다.
