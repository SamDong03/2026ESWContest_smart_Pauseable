Pauseable 배포 인계 — 전체 기기 시연 검증 직전

현재 단계
PC 소스 구조·명칭·배포 입력을 정리한 상태이다. 실제 기기 설치, 클라우드 설정 변경, Git 커밋·push 및 전체 기기 시연은 수행하지 않았다.

디렉터리
Pauseable.apps/guardian: Flutter 보호자 앱. 앱과 Pi5 웹 UI는 환경에 맞춰 새로 빌드한다.
Pauseable.apps/api: 보호자·기기 API와 로컬 게이트웨이.
Pauseable.ai/ha: HA 수집·추론·반복 행동·세탁기 시연 실행 코드.
Pauseable.ai/mmwave: 경로 특징·모델·mmWave 추론.
Pauseable.ai/voice: GPU 음성 학습 Worker와 학습·검증 파이프라인.
Pauseable.edge/central: Pi5 중앙 앱과 음성·가전 동작.
Pauseable.edge/voice-model: Pi5 음성 모델 검증·교체.
Pauseable.edge/actions/youtube: Pi5 YouTube 브리지.
Pauseable.edge/camera: Pi4 카메라 버퍼·대표 사진 선택.
Pauseable.edge/mmwave-relay: Pi3 센서 릴레이·계약 검증·시연용 입력 생성.
Pauseable.edge/central/mmwave-tools: 독립 C++ mmWave 수신기 빌드.
Pauseable.integrations/home-assistant: 날씨·조명 및 지역 설정 API.
Pauseable.contracts: 공유 스키마와 예제.
Pauseable.third_party: Piper·nlohmann 원본 라이선스와 외부 소스.
Pauseable.deploy: 서비스 설정·기기별 소스 묶음 생성기·이전 설정 대응표.

PC에서 기기별 소스 묶음 생성
저장소 루트에서 Python 3.12로 다음 명령을 실행한다.
python Pauseable.deploy/mmwave-autostart/package_devices.py --verify-source-manifest
python Pauseable.deploy/mmwave-autostart/package_devices.py --output deployment-bundles
pauseable-pi3.tar.gz, pauseable-pi4.tar.gz, pauseable-pi5.tar.gz가 만들어진다.
각 압축은 같은 이름의 최상위 폴더와 BUNDLE.sha256을 포함한다. 압축 해제한 폴더에서 sha256sum -c BUNDLE.sha256으로 내용을 확인한다.
이는 소스·설정 묶음이다. webOS SDK가 필요한 Pi5 앱 바이너리, 휴대폰 설치 APK, 개인화 ONNX·녹음·비밀 환경 파일은 포함하지 않는다.

기존 설치에서 새 이름으로 전환하기 전
Pauseable.deploy/migration/legacy-to-pauseable.json에 이전 이름과 현재 이름의 대응이 있다.
기존 모델·환경 파일·개인 기록·데이터베이스·서비스 정의·Docker 이미지 ID를 먼저 별도로 보존한다.
MQTT 주제, 환경 변수, HA 가상 기기 ID, 서비스·컨테이너·앱 ID를 같은 배포에서 맞춘다.
이전 실행 캐시 DB는 현재 모델 파일 해시와 구분해 새 경로에서 시작한다. 기존 개인 기록은 삭제하지 않고 별도 검토해 이관한다.
기존 장치에서 사용하던 사용자·그룹·SSH 키·장치 주소는 대응표와 실제 상태를 대조해 이관한다. PC 소스 정리가 장치 상태를 자동 변경하지 않는다.

Pi3
pauseable-pi3 묶음의 Pauseable.deploy/mmwave-autostart/pi3/install.sh --check로 구성만 확인할 수 있다.
실제 설치는 pauseable 사용자·dialout 권한·Pi5 주소·SSH 접속을 준비한 뒤 명시적으로 --apply를 사용한다.
새 서비스는 pauseable-mmwave-relay.service이며 설치만으로 enable/start하지 않는다.

Pi4
Pauseable.edge/camera를 Docker 빌드 context로 사용한다.
docker build -t pauseable-camera:final Pauseable.edge/camera
camera.env.example의 API 주소·기기 인증 값을 기기에 맞게 준비하고, home-assistant 설정의 현재 엔티티·토픽을 맞춘다.
실제 촬영·문열림 전후 대표 사진 확인은 이후 전체 시연 단계에서 수행한다.

Pi5
mmWave 컨테이너는 저장소 또는 pauseable-pi5 압축 해제 폴더를 빌드 context로 사용한다.
docker build -t pauseable-wandering-publisher:final -f Pauseable.deploy/mmwave-autostart/pi5/Dockerfile .
이 Dockerfile은 Python 공식 기반 이미지에서 현재 소스·스키마·모델을 함께 설치하며 이전 개인 이미지에 의존하지 않는다.
개별 장치에 맞는 publisher.env를 /var/lib/pauseable-wandering/publisher.env에 준비한다.
FIFO 준비 스크립트는 /data/pauseable/bin/pauseable-mmwave-prepare-fifo.sh, unit은 pauseable-wandering-publisher.service를 사용한다.
unit의 /var/lib/pauseable-wandering 상태 경로, /run/pauseable-wandering-input.fifo, ha-docker-engine.service 및 실제 읽기·쓰기 권한을 설치 전에 확인한다.
중앙 앱·YouTube 브리지는 대상 webOS SDK로 빌드하고 현재 앱 ID로 설치한다. 음성 모델과 Piper 런타임 파일은 기존 모델을 보존한 상태로 현재 경로에 준비한다.
YouTube 브라우저 이미지는 대응표의 현재 태그인 pauseable-youtube:1로 준비하고 chromium-seccomp.json도 현재 경로에 이관한다. 브라우저 HOME은 기존 실행 UID 1004의 tmpfs로 준비하므로 기존 이미지의 내부 홈 폴더 이름에 의존하지 않는다.
단순 폴더 복사만으로 C++ 바이너리·웹 UI·서비스 설치가 완료되지는 않는다. 장치의 현재 상태를 확인한 후 해당 구성 요소를 함께 전환한다.

앱·클라우드 설정
Flutter 앱과 Pi5 웹 UI는 대상 API 주소·인증·Firebase 설정을 넣어 새로 빌드한다.
GitHub Android 빌드 변수·secret 이름은 PAUSEABLE_FIREBASE_ANDROID_CONFIG_JSON, PAUSEABLE_APP_TOKEN을 사용한다. 실제 저장소의 변수·secret 복사·갱신은 별도 단계이다.
실제 GitHub 저장소 이름과 원격 주소는 변경하지 않았다. 코드 안의 기존 저장소 참조는 사실에 맞는 주소로 유지한다.

다음 단계
기기별 백업·설치·서비스 전환과 휴대폰 앱 설치를 마친 뒤 Pi3/Pi5 센서 입력, Pi4 사진, HA 상태, 음성·가전 동작, 보호자 앱 알림을 연결해 전체 시연을 검증한다.
실행·빌드 지시문과 라이선스 고지는 유지했다. 생성 도구 실행 후 일반 주석이 다시 생길 수 있어 최종 제출 직전에 다시 검사한다.
