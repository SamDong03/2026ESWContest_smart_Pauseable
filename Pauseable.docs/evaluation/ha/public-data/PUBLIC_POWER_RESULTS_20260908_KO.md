# 엑셀 공개 데이터 실제 반영 결과

작성일: 2026-09-08. 최종 실험: `experiments/*_v2`.

## 먼저 답변

이전에는 UK-DALE 등 문헌 검토와 별개로 일반 UCI 전력 데이터 실험을 했으며,
UK-DALE·REFIT 원자료를 우리 코드에 넣어 학습한 상태는 아니었다.
이번에는 엑셀에 적힌 UK-DALE와 REFIT의 실측 전력 데이터를 직접 다운로드하고,
가전별 전처리·특징 추출·Isolation Forest 및 Autoencoder 학습·평가까지 수행했다.

추가한 것은 공개 전력 데이터를 재사용할 수 있는 별도 분석 경로이다.
Pi에서 돌아가는 기존 HA 서비스, 규칙 경보, 가전 제어, 우리 집 모델은 바꾸지 않았다.
공개 데이터 모델을 우리 집에 바로 적용하는 것은 이번 결과로 정당화할 수 없다.

`AIoT_AI_Model_Data_Design.xlsx`의 `데이터없는_AI학습전략` A98/B98, A99 및

단위, 시간대, 결측, 사용 구간 기준을 구현했다.

이번 요청에는 가전별 전력 실측을 제공하는 두 자료가 가장 직접적으로 맞는다고 판단했다.

## 실제 사용량과 결과

전체 데이터셋이 아닌 공식 파일의 앞부분을 크기 제한으로 선택했다.
UK-DALE는 채널마다 약 8 MB, REFIT는 House 2 CSV 약 24 MB이다.
REFIT의 두 가전은 같은 424,206개 시각 행의 서로 다른 열이므로
서로 다른 가정의 기록이나 독립적인 두 데이터셋으로 세면 안 된다.

| 데이터 / 가전 | 원자료 행 | 전체 특징 구간 | 품질 통과 구간 | 학습 / 보정 / 평가 | IF 신호율 | AE 신호율 |
|---|---:|---:|---:|---|---:|---:|
| UK-DALE 전자레인지 | 614,047 | 6,304 | 6,233 | 3,691 / 1,199 / 1,247 | 11.31% | 0.48% |
| UK-DALE 세탁기 | 614,255 | 6,314 | 6,175 | 3,657 / 1,187 / 1,235 | 3.32% | 3.48% |
| REFIT 전자레인지 | 424,206 | 4,662 | 1,738 | 1,006 / 300 / 348 | 0.29% | 3.16% |
| REFIT 세탁기 | 424,206 | 4,662 | 1,738 | 1,006 / 300 / 348 | 11.21% | 10.63% |

신호율은 최종 평가 구간 중 `attention` 또는 `risk`로 나온 비율이다.
이 표는 정확도·재현율·실측 오탐률이 아니다. 실제 이상 정답이 없기 때문이다.
낮은 신호율이 좋은 모델이라는 뜻도 아니다. 학습·보정·평가 사이의 누출 방지
간격 때문에 세 분할의 합은 품질 통과 구간보다 작다.

UK-DALE 원자료 기간은 UTC 2013-05-20~07-03이다.
REFIT 원자료는 2013-09-17~10-20이지만 보수적인 품질 기준을 통과한 구간은
일부에 집중됐다. REFIT는 사용 가능한 특징이 있는 날짜가 16일이며,
최종 평가 구간은 09-30~10-07이다. 전체 기간을 연속·완전 관측했다고 보면 안 된다.

## 공부할 때 볼 핵심 변경

### 1. 전력에서 에너지를 계산

전력 W와 에너지 Wh는 다르다. 예를 들어 관측된 120 W가 2시간 유지되면
`120 * 7200 / 3600 = 240 Wh`이다. 이 단위 변환을 실제 코드와 테스트에 넣었다.
각 표본은 UK-DALE 6초, REFIT 8초까지의 관측을 지지하며 다음 표본이 먼저
도착하면 그때까지로 제한한다. 공백 시간의 전력을 임의로 채우지 않는다.
표본 간격이 흔들리면 에너지를 과소 추정할 수 있으므로 관측 비율도 함께 저장한다.

### 2. 켜짐 횟수를 안정적으로 계산

잠깐의 소비전력 튐을 사용 1회로 세지 않도록 최소 작동·정지 시간을 둔다.
UK-DALE 전자레인지는 저자 메타데이터의 200 W / 12초 / 30초를 참고했다.
세탁기는 20 W / 1800초 / 160초이다. 실제 시작이 확인된 시점에 횟수를 반영하며,
종료가 확인돼야 평균 완료 시간이 특징에 들어간다. 미래에 알게 된 종료 결과를
과거 특징에 미리 넣는 누출을 막는다. 이 구현은 NILMTK 결과와 동일하다는 주장이 아니다.

### 3. 결측을 정상으로 숨기지 않기

REFIT `Issues` 오류 표시 3,747행을 가전별 분석에서 제외했다.
음수·범위 초과·충돌 중복은 결측으로 처리하며 2시간의 관측 지지율이
95% 미만이면 해당 특징을 NaN으로 남겨 학습에 넣지 않는다.
이미 원자료에서 채운 REFIT의 0이나 이전 값은 전부 복구할 수 없다.

특히 REFIT 세탁기는 추정된 사용 시작 4건 모두 완료를 확정하지 못했고,
완료 사용 구간은 0건이었다. 학습 구간에서는 횟수·완료시간 특징이 상수였다.
이 자료 선택과 임계값으로 세탁 빈도·평균 시간을 잘 추출했다고 주장할 수 없다.
명령은 성공했지만 이 조합은 배포 후보가 아니라 품질 한계를 드러낸 비교 사례이다.

### 4. 모델은 같은 입력으로 비교하되 운영과 분리

IF는 특징 공간에서 쉽게 분리되는 표본을, AE는 입력 복원 오차가 큰 표본을
이상 후보로 본다. 이번 입력은 관측 에너지, 평균 전력, 임계값 이상 시간,
시작 횟수, 완료 횟수, 평균 완료 시간, 야간 시작, 시간·요일 sin/cos 11개다.

모델은 기존 구현을 재사용했다. 시간순 60/20/20 경계, 보정 구간의
95/99 백분위 임계값, 학습 구간만의 표준화를 사용한다.
긴 사용 구간의 의존성까지 고려해 분할 사이에 최소 481분을 비웠다.
공개 데이터의 `source_type=public`을 유지했으며, `local`로 표시된 우리 집
입력을 이 모델에 넣으면 점수 대신 `incompatible_source`가 나오는 것을 확인했다.

## 내 판단과 적용 범위

공개 자료에서 우선 가져올 것은 **전처리 방법, 특징의 정의, 모델 비교 절차**이다.
이번 전자레인지 두 사례만 봐도 IF와 AE의 신호율 방향이 달랐다.
공개 자료에서 경보가 적은 모델 하나를 고르는 방식은 추천하지 않는다.

우리 집 가전에 전력 W 센서가 있다면 같은 특징 추출기를 재사용할 수 있다.
그때는 센서 단위·갱신 방식·기기별 임계값·한국 시간대를 확인하고 우리 집 데이터로
별도 보정해야 한다. 지금은 일반 `timestamp,power_w` CSV 입력까지 구현했으며,
이 경로의 HA 센서 자동 수집과 Pi 상시 연결은 추가하지 않았다.
전원·모드만 제공하는 기기는 기존 HA 이벤트 경로를 계속 사용한다.

## 검증과 파일

- 전체 자동 테스트 44개 통과: 기존 25개 + 이번 19개.
- 실제 공개 데이터 4개 조합의 모델 저장·재추론 결과 일치 확인.
- 시간 분할 간격, 학습 전용 표준화, 공개 모델의 local 입력 차단,
  불완전 이력 점수 차단 확인.
- 다운로드 URL·버전·부분 추출·SHA-256·라이선스 기록.
- 원래 `ha_ai`에 신규 파일 10개를 반영했다: 소스 4개, 테스트 1개, 프로필 4개, 설명서 1개. 복사 후 SHA-256 일치를 확인했다.
- 원래 프로젝트 경로에서도 전체 44개 테스트가 다시 통과했다. `original_source_tests.log` 참조.
- 원자료와 학습 모델은 이 작업 폴더 아래에 분리 보관한다. Pi 배포나 개인 모델 교체는 하지 않는다.

실행 결과: `benchmark_summary.csv`, `verification.json`, `experiments/*_v2/experiment.json`.
과정: `WORK_LOG.md`, `actions.jsonl`, 명령별 `.log`.
