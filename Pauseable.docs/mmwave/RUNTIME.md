# 구간 분석 개선판

## 기존 코드 대비

| 항목 | 기존 연결 | 개선 연결 |
|---|---|---|
| 구간 RF | 기존 v1 9개 특징 joblib | v2 JSON RF 36개 특징 기본, v1 명시 사용 가능 |
| 기준값 | 통합 코드에 0.5 고정 | 선택 모델에 저장된 0.66 사용 |
| 지속성 | 개인 기록이 있는 연속 3개 창 | 형태와 개인을 분리해 3개 이상 창 및 90초 이상 확인 |
| 경계 흔들림 | 1회 기준값 하락으로 증거 소실 | 후보 생성 후 낮은 해제 기준으로 유지 여부 확인 |
| 개인 정보 없음 | 형태 판단까지 차단 | 형태 검토 가능, 개인 분석은 unavailable |
| UTC 미동기 | 형태 계산도 차단 | 경고 유지, 상대시간 형태 분석 가능; 개인 기록 저장은 보류 |
| 시계 회귀 패킷 | 잘못된 seq로 후속 정상 패킷 차단 가능 | 유효한 uptime 확인 후 seq 갱신 |
| 상태 저장 | 모든 스트림이 시간 상태 하나 공유 | 센서·출처·대상별 분리, 세션 전환 초기화 |
| 재실행 | 모델/정책 변경 후 이전 결과 재사용 가능 | 입력·RF·정책·개인 기준선 버전 충돌 거부 |
| 모델 파일 | 일부 헤더만 확인 | 노드·인덱스·순환·유한수·크기 제한 검증 |
| 출력 | 배너·결과·집계 혼재 | 구간 추론은 JSON 결과만, 선택적 stderr 집계 |

## 시험용 시간 정책

- 최소 3개 연속 구간이면서 총 90초 이상 높은 증거가 있어야 후보가 됩니다.
- RF 시작 기준은 모델 파일의 값입니다(현재0.66). 해제 기준은 시작 기준에서0.10을 뺀 값입니다.
- 개인 희귀도는 비교 자료의95백분위 이상을 시작,90백분위 미만을 해제로 사용합니다.
- 후보 생성 전 경계 근처 점수는 높은 증거로 누적하지 않습니다.
- 후보 생성 후에는 해제 기준 아래로 내려갈 때 해제됩니다. 이는 출력 흔들림을 줄이기 위한 정책입니다.
- 단절·저품질·모델 변경은 증거를 초기화합니다. 겹치거나 역순인 같은 스트림 구간은 누적하지 않습니다.
- 개인 기준선 또는 개인 지정이 바뀌면 개인 증거만 초기화하고 형태 증거는 유지합니다.
- 고빈도 관측이 끊기면 구간 생성이 멈출 수 있습니다. 마지막 저장 후보를 현재 상태로 계속 표시하면 안 됩니다.
  실시간 연결에서는 기존 수신기의 stale/silent 상태를 반드시 함께 사용해야 합니다.

이 숫자는 **소프트웨어 동작 시험용 정책**이지 실제 배회 시작 시간·임상 경계가 아닙니다.
90초가 지났다는 것만으로 사람이 배회 중이라고 확정하지 않습니다.
점수와 시간 조건의 결합 성능은 실측 라벨이 없어 정확도로 평가하지 않았습니다.

## 결과 읽기

- `shape_review_candidate`: 반복 경로 형태 증거가 지속됨.
- `personal_change_candidate`: 개인 과거 분포와 다른 형태가 지속됨.
- `combined_review_candidate`: 두 증거가 모두 지속됨.
- `partial_evidence`: 개인 비교 자료 없이 형태 증거만 확인 중.
- `no_current_rule_flag`: 이번 시험 규칙에서 후보 아님. 안전/정상 확정이 아님.
- `insufficient_evidence`: 관측이 부족해 보류. 비배회로 간주하지 않음.

결과에는 RF 점수·모델 해시·특징 버전·개인 기준선 버전·누적 시간·판단 근거가 남습니다.
`synthetic_shape_class`는 합성 모양 분류이고 실제 배회 확정 결과가 아닙니다.
`alert=false`는 유지합니다. 희귀하지 않다고 반복 형태의 후보를 차단하지 않습니다.

## 보존한 것

학습 모델, 특징 소스, SmartCare 데이터, 기존 runs/DB, Pi5 파일은 변경하지 않습니다.
기존 개인 기록은 9개 특징 규격 그대로 유지합니다. 36개 RF 특징을 기존 개인 DB에 섞지 않습니다.
새 버전으로 동일 입력을 다시 평가할 때는 별도 DB를 사용하세요.
